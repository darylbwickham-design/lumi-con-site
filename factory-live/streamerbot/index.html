Create a Factory Live action

Use this setup if you want to attach a reward or command in Streamer.bot’s action editor. Complete the game and bridge setup and leave the bridge running on the same Windows PC.

  1. Download StreamerBotWebhook.cs and open it in a text editor. For this example, find the Preset constant near the top and set it to "surprise-me". Use the preset name from the preset list for other effects.
  2. In Actions & Queues → Actions, right-click the action list and choose Add. Name the action Factory Live Surprise Me.
  3. In Sub-Actions, right-click and choose Core → C# → Execute C# Code. Paste the entire C# file. If the editor can’t find HttpClient or JObject, use the C# editor’s references to add System.Net.Http.dll or the Newtonsoft.Json.dll shipped with Streamer.bot.
  4. Click Save and Compile. When compiled, the action reads Factory Live’s local link file and sends the selected preset. The action arguments factoryLiveStatus and factoryLiveResult report the bridge’s response.

Connect a Twitch reward

  1. Connect the Twitch broadcaster account. Under Platforms → Twitch → Channel Point Rewards, right-click and select Add, or use a reward already synced from Twitch.
  2. For a new reward, enter Factory Live Surprise Me, set its cost to 1 and global cooldown to 60 seconds, and save it.
  3. Return to the Factory Live action. In Triggers, right-click and choose Twitch → Channel Reward → Reward Redemption. Select the specific reward you want to bind.
  4. Load a test save, unpause, and arm Factory Live. Enable the reward and run one redemption. Check Action History in Streamer.bot for the action and node bridge.mjs status for the game connection.

Bind each reward once if Lumia is also running. Use a specific reward rather than the Any trigger so unrelated redemptions don’t spawn effects. Reward Redemption documentation

Connect a chat command

  1. In Commands, add an exact-match command such as !surprise. Enable it for the platform you use and set its permissions and global cooldown.
  2. In the action’s Triggers, add Core → Commands → Command Triggered and select !surprise.
  3. Test in chat once the local game is ready and armed. To bind !nukewave, create a second action with "nuke-carpet" as its Preset and attach that command.

Other triggers can use the same action. For example, add a raid trigger to a creature-roulette action or bind a hotkey to turn-around. Command Triggered documentation

Optional WebSocket setup

Use the WebSocket route to map several chat commands or Twitch rewards in one config file. This route works without the C# action. Each command or reward should use one route.

  1. In Servers/Clients → WebSocket Server, set the address to 127.0.0.1, confirm the port and endpoint (defaults 8080 and /), and start the server. Keep your WebSocket password enabled if you already use one.
  2. From the bridge folder, copy bridge.config.json into bridge.local.json. Edit that copy. If you already have a local config, keep it and edit its existing streamerBot block.
  3. Set streamerBot.enabled to true. Check the url matches your server. Create the matching commands in Streamer.bot. For a reward, right-click it in Channel Point Rewards and choose Copy Reward ID. Add that ID as a key under rewards with the preset name as its value.

Example streamerBot settings block. Replace the sample UUID with your reward’s ID.

{
  "enabled": true,
  "url": "ws://127.0.0.1:8080/",
  "commands": {
    "!nukewave": "nuke-carpet",
    "!roulette": "creature-roulette",
    "!surprise": "surprise-me"
  },
  "rewards": {
    "00000000-0000-0000-0000-000000000000": "cluster-rain"
  }
}

Stop any running bridge with Ctrl+C. If Streamer.bot requires a password, run the first line below. Run the second line in the same PowerShell window. When you see Streamer.bot WebSocket subscribed, load your test save and arm the bridge as usual.

$env:FACTORYLIVE_STREAMERBOT_PASSWORD = Read-Host "Streamer.bot WebSocket password" -MaskInput
node bridge.mjs serve bridge.local.json

Troubleshooting

Webhook reports 409 or 429

409 means the bridge or selected effect is unavailable, often because the game is disarmed or unready. 429 means a cooldown, queue limit, rate limit, or in-game frame-time pause is active. Review the response in the action history or log.

Streamer.bot approves the reward but no effect starts

Check the command name or reward ID mapping, confirm the action used the intended preset, and run node bridge.mjs status. A 202 response confirms queue entry. The game can defer the wave until it has room.

The WebSocket doesn’t subscribe

Check the server is started and the URL matches its bind address, port, and endpoint. If password authentication is enabled, provide FACTORYLIVE_STREAMERBOT_PASSWORD in the same shell that starts the bridge.
