Crash warning

Repeated waves and high multipliers can freeze or crash Satisfactory, especially during respawn. Make a separate save before enabling chat. Keep Disarm Bridge on a private Lumia button. It clears queued effects; creatures already in the world stay there.

Install and start

Install 0.9.0-chaos.16 using the installation guide, then load a save as host. The bundled bridge starts and arms automatically. If you used the old standalone bridge, close it before launching Satisfactory.

Connect your stream

Use the Lumia Stream guide for the bundled commands and Twitch rewards, or the Streamer.bot guide for a C# action.

HTTP webhooks

Use the port and webhookToken from %LOCALAPPDATA%\FactoryLiveChaos\link.json. The default base URL is http://127.0.0.1:37129. Send Authorization: Bearer <webhookToken>. Use Content-Type: application/json for POST requests.

  • GET /v1/connection checks whether the game is connected, ready, and armed.
  • GET /v1/presets lists preset IDs and creature variants.
  • GET /v1/mobs lists named endpoints and shows which creatures your world can spawn.
  • POST /v1/trigger queues an effect.

Request a group

Send {"qty":1,"multiplier":5} to POST /v1/mobs/crab-hatcher for five hatchers in one group. Quantity counts base placements; the multiplier counts creatures per successful placement, including the first. A blocked base keeps its multiplier while queued. For three groups of five, set qty to 3. Whole-number multipliers from 1 to 100 work on hostiles and the Chaos preset. Wildlife is available through individual endpoints.

Keep the token on the host PC. A cloud chatbot needs a local integration such as Streamer.bot or Lumia to reach this loopback address. HTTP 409 means the action is unavailable in the current state; check the response and host readiness. On 429, allow the cooldown or queue to clear.

Example trigger requests

{"preset":"nobelisk-chaos"}
{"entityId":"stinger","variant":2,"qty":1}

The first request triggers !nukem. The second requests one Elite Gas Stinger. HTTP 202 confirms that the bridge queued it. If you retry the same redeem, reuse its eventId.
